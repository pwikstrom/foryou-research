Backends

Machine annotation

The backend that annotates videos. Model and generation parameters (temperature, thinking budget, media resolution, max output tokens) are set in the [machine] section of config/config.toml and require a rebuild/redeploy to change.

Switching the backend changes how new annotations are made from now on: a new annotation version (av_…) becomes active and future annotations are stamped with it. Existing annotations are untouched, and analyses keep reading the preferred version — nothing needs to be refreshed until you re-annotate videos and promote the new version on the Versions page.

Embeddings

The model that embeds annotated videos for the Semantic Space map. Chosen independently of the annotation backend — with both set to a local backend, embeddings and the semantic map run with no cloud calls (micro-niche names then come from each micro-niche's top terms instead of Gemini).

Changing the backend takes effect on the next embeddings refresh, which re-embeds the corpus under the new model (existing vectors are kept, so switching back costs nothing). To apply it, run Embeddings → Refresh and then Video map → Rebuild under Data Pipeline → Dataset Assembly; until then the Semantic Space map keeps showing the previous model and reports itself as stale.

Second machine

For a Hub whose storage is shared with a second computer (for example a Mac running a local model) that annotates the videos this Hub has not annotated. That computer works through its own list, the backlog, and never the annotation queue above. It gives way to this Hub: it skips videos queued here, and where both have annotated a video, studies read this Hub's annotation. A Hub that runs on one computer does not need this; choose the annotation backend above instead. Setting up the second computer: DEVELOPING.md, “Backlog Annotation on a Second Machine”.
